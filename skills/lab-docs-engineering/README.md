# lab-docs-engineering · 科研文档工程化 Skill（v3）

一个可移植的 AI 助手 Skill（Cursor / Claude Code 等支持 `SKILL.md` 的工具都能用）：把「实验记录 / 决策留痕 / 知识库整理 / 收尾归档」变成助手每次自动、按统一规范完成的动作。
v3 起专门处理**多个 AI 会话并行**时文档不同步的问题。装一次，跨你所有科研仓库复用。

## 为什么用它

科研进度的瓶颈常常不是算力，而是**连续性与交接**——重复踩坑、baseline 混表、找不到当前主线、结案后证据丢失。
同时开几个 AI 会话做不同课题时还会多一个问题：每个会话只更新自己那块，入口、总纲、待办表里的数据版本、在用模型、作业状态就开始落后、互相矛盾。

这个 Skill 用五条铁律约束每次动作：

1. **决策 + 依据被固化**：Go/No-Go 与判据来源写清；用户的决定（含「暂不做」）也写进文档。
2. **不跨路线混表**：不同实验线 / 数据版本 / 评估集的指标不裸比。
3. **可发现性**：新人或新会话从入口 README 几分钟定位「当前主线 + 最新结论 + 下一步」。
4. **归档不丢证据**：收尾后现行文档仍保留 Go/No-Go 与证据路径。
5. **单一事实来源，事实以产物为准**：跨文档事实只有一个规范位置；文档状态对不上运行产物、调度器、进程、git 时，以产物为准。

## v3 新增（2026-10）

- **多会话并行协议**（`parallel-sessions.md`）：开工检查（先读规范位置的现状、看谁在改什么）→ 占用共享资源时在受影响的块留「跨线影响告知」→ 任务结束做**收尾同步**（跟踪 → 块 README → 跨文档事实及其镜像 → 推进记录 → 撤销告知）。
- **全量同步审计**（`sync-audit.md`）：说一句「把文档更新到最新」，助手按步骤做——先建事实表（产物 > 调度器 / 进程 > git > 跟踪 > 汇总文档）、分清活文档与快照、扫过时说法、逐条核实、定点修改、修并发写坏的结构、补推进记录、按四组汇报。
- **事实登记表**（profile `fact_registry`）：每条跨文档事实的规范位置、镜像位置与核实方式，收尾同步和全量审计都按它传播。
- **块内收敛**：每块只留 README + 一份跟踪 + 最新报告；归档时全仓改链接、加横幅、登记旧→新路径。
- 模板不再使用 HTML 注释；新增指针条目、后续状态补记、跨线影响告知、当前状态块、汇报模板。

## 架构：通用本体 + 每仓 profile

- **通用本体**（本目录，项目无关）：装到个人技能目录，跨所有仓库共享。
- **项目 profile**（`<repo>/.cursor/skills/lab-docs-engineering/PROJECT_PROFILE.md`）：声明本仓的文档路径、路线分册、入账方式、归档目录、活文档清单、事实登记表、共享资源。首次使用时向导自动扫描生成。

一处升级本体，所有仓库同时受益；各仓库的差异全部收在自己的 profile 里。

## 安装

```bash
# Cursor（个人级，跨所有仓库）
mkdir -p ~/.cursor/skills && cp -r lab-docs-engineering ~/.cursor/skills/

# Claude Code（个人级）——可以直接链接到同一份本体，避免两份不同步
mkdir -p ~/.claude/skills && ln -s ~/.cursor/skills/lab-docs-engineering ~/.claude/skills/lab-docs-engineering

# 或 项目级：随某个仓库分发给协作者
cp -r lab-docs-engineering <your-repo>/.cursor/skills/
```

（从 `xiuyangFeng/person-skills` 下载后，把 `lab-docs-engineering/` 整个目录放到上述任一位置即可。）

## 30 秒上手

1. 在目标仓库说 **「初始化实验记录」**：助手扫描仓库 → 草拟 `PROJECT_PROFILE.md`（含活文档清单和事实登记表草稿）→ 你确认 / 微调。空仓库会先建最小 `docs/` 骨架。
2. 正常干活。任务做完，助手会主动做收尾同步；也可以说 **「记一下」**。
3. 并行开了很多会话、文档可能不一致时，说 **「把文档更新到最新」**（全量同步审计）。
4. 阶段收尾说 **「归档」** 或 **「只留最新和跟踪」**。

常用触发词：`记一下` / `写推进记录` / `同步文档` / `文档更新到最新` / `全量同步` / `正式入账` / `整理知识库` / `收尾交接` / `归档` / `切卷` / `初始化实验记录` / `重新配置`。

## 适用范围

任何做实验、需要留痕与交接的科研仓库——GNN / CFD / 医学影像 / NLP / 通用 ML 皆可。领域差异全在 profile 里表达，本体不含领域假设。参考：

- [`examples/generic-ml.profile.md`](examples/generic-ml.profile.md) — 通用最小项目
- [`examples/gnn-digital-twin.profile.md`](examples/gnn-digital-twin.profile.md) — 复杂多路线、多会话并行的真实项目

## 文件地图

| 文件 | 作用 |
| --- | --- |
| `SKILL.md` | 主体：五条北极星、能力地图、各工作流、自检 |
| `parallel-sessions.md` | 多会话并行协议：开工检查、跨线影响告知、收尾同步、编辑礼仪、冲突处理 |
| `sync-audit.md` | 全量同步审计：事实源优先级、活文档 / 快照、过时扫描、逐条核实、安全编辑、结构修复、汇报 |
| `templates.md` | 推进记录、指针条目、后续状态补记、跨线影响告知、当前状态块、入账、汇报、起步骨架 |
| `boundaries.md` | 职责边界、多会话边界、硬禁止 |
| `archive-checklist.md` | 块内收敛、归档、滚动切卷清单 |
| `wizard.md` | 三模式配置向导与 profile 结构 |
| `examples/` | profile 参考样例 |

## 给推广者的提示

- 本体保持**项目无关**：具体路线名、数据版本名只出现在 profile 或 examples 里。
- 想给一个仓库定制默认行为，改它的 `PROJECT_PROFILE.md`，不要改本体。
- 从 v2 升级：本体直接替换即可；在各仓库说「重新配置」可让向导补上 `live_docs`、`fact_registry`、`shared_resources` 等新键（不补也能用，审计时会按分层表推断）。
