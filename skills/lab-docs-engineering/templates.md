# 模板

字段以当前仓库 `PROJECT_PROFILE.md` 的 `required_fields` 为准；下面是通用默认。
所有模板都不用 HTML 注释（部分 Markdown 渲染器会把它显示出来或报错），可选项用文字标明。

## 推进记录（文首插入，完整条目）

```markdown
## YYYY-MM-DD｜主题 · 动作 · 状态

- **本次主要修改**：…
- **对应代码/文档**：…（链接到跟踪节、工具路径、配置目录）
- **推进到实验步骤**：…（作业号、run 目录、完成到哪一步）
- **当前状态判断**：…（绝对状态词；下一步或待用户决定的事）
```

科研可选字段（profile 勾选才写）：**背景假设**、**方法变更**、**关键指标**（写明数据版本 / split / seed / 对照，禁止跨路线裸比）、**Go-NoGo**（Go / No-Go / 待定 — 判据来源）、**下一步**。

书写规则：插在文件说明块之后、第一条旧记录之前；一条一件事；指标带来源路径；不写相对时间词；时间到小时并注明时区口径。

## 指针条目（事实已写在跟踪里时）

```markdown
## YYYY-MM-DD｜主题（指针）

- **本次主要修改**：一两句结论（关键数字可以带，但不复制表格）。
- **对应文档**：[块跟踪 §N](相对路径)、[其他相关处](相对路径)。
```

## 后续状态补记（历史小节、决策记录、快照之后）

```markdown
**后续状态（YYYY-MM-DD 补记，不改上面的原文）**：第 k 条——…（现状一句话 + 链接）；第 m 条——…。
```

用于：已结束的小节、用户裁定原文、执行记录里「预计…」最终没发生或结局不同。不要改原文，只在后面补。

## 跨线影响告知（写在受影响块的 README）

```markdown
**跨线影响告知（YYYY-MM-DD HH:MM，来自 <哪条线 / 哪一节>）**：<占用 / 依赖了什么>，从 <时间> 起，预计 <时间> 释放。
<对方不要做什么>（例如：在 <日期 / 条件> 之前不要删除或重建 <路径>）。释放后在此改为「已释放（日期）」。
```

## 当前状态块（块 README 顶部）

```markdown
## 当前状态（YYYY-MM-DD）

- **<事实 / 子线 1>（状态词，日期）**：一两句现状 + [跟踪 §N](…)。
- **<事实 / 子线 2>**：…
- **已知限制 / 待用户决定**：…
```

规则：标题日期随每次更新改；被取代的旧条目删掉或改成「（已由 YYYY-MM-DD 的 X 取代）…」一句；长内容放跟踪，这里只放结论与链接。

## 事实登记表条目（profile `fact_registry`，或 `fact_registry_doc` 指向的仓库文档里的一行表格）

```yaml
- fact: "部署在用的模型 / 版本"
  canonical: "docs/<部署块>/README.md#当前状态"
  mirrors: ["docs/README.md", "docs/<总纲>.md", "docs/<总览>/README.md", "docs/<待办>.md"]
  verify: "服务健康接口版本 + git log + 发布目录"
```

## 正式入账（Markdown 最小集）

```markdown
### <exp_id>｜<一句话目的>

| 项 | 值 |
| --- | --- |
| 配置 | `path/to/config.json` |
| 数据版本 / split | … |
| seed | … |
| 状态 | 草稿 / 已提交 / 训练中 / 完训 / 中断 / 作废 |
| 关键指标 | …（来源文件与字段） |
| 产物 | `outputs/.../` |
| 对照 | <baseline exp_id> |
| 结论 | … |
```

xlsx / CSV 对齐：按 profile `ledger.fill_spec` 或指定的更新工具填；只填规范列出的列，不知道的留空并在推进记录注明待补；有 `csv_index` 时保证 exp_id、配置、输出目录与磁盘一致；没有工作簿就只维护 Markdown，不伪造。

## 分析回填（短）

分析 Skill 出结论后，本 Skill 只追加：推进记录一条（关键指标 + Go-NoGo）、跟踪状态行、块 README 当前状态、待办表对应行与其变更记录、`fact_registry` 镜像（若结论改变了跨文档事实）。不展开长篇原因分析，指向分析产物目录。

## 汇报（每次动作后给用户）

```markdown
**改了哪些文件**（分组）：入口 / 总纲 / 各块 README / 跟踪 / 待办 / 推进记录 / profile / 记忆
**核查中发现并改正的错误**：1. … 2. …（每条写依据：产物路径、命令、提交号）
**有意没改的**：快照与历史小节（只补记）、非 Markdown 文件、别的会话正在动的区域
**需要你决定的**：…（选项与各自代价）
```

动作很小（只写一条推进记录）时，压成 2–3 条要点即可。

## 起步骨架（scaffold）

供向导「模式 B」在空仓库建最小结构。路径按 `docs_root` 调整；只建最小结构，不预设复杂分册。

### 入口 `docs/README.md`

```markdown
# 项目文档索引

> 更新时间：YYYY-MM-DD

一句话说明本项目在做什么。

## 现在先看什么（当前主线）

- **当前主线**：<正在推进的路线 + 最新结论 + 下一步>
- [推进记录](02-推进与变更/代码修改与实验推进记录.md)（只读文首 3–5 条）
- [知识库整理规范](00-规范与记录/项目知识库整理规范.md)

## 分层导航

| 层 | 位置 | 放什么 |
| --- | --- | --- |
| 入口 | 本文件 | 只导航，指向当前主线 |
| 规范 | `00-规范与记录/` | 口径、填写规范、整理规范 |
| 推进记录 | `02-推进与变更/` | 时间倒序凭证（最新在上） |
| 证据 | `outputs/` 等 | run 产物，文档只引用路径、不搬运 |
```

### 推进记录空文件 `docs/02-推进与变更/代码修改与实验推进记录.md`

```markdown
# 代码修改与实验推进记录

> 每完成一个任务 / 实验后，在文首追加一条（最新在上）。标题：`## YYYY-MM-DD｜主题 · 动作 · 状态`。
> 状态用绝对词（已提交 / 训练中 / 完训 / No-Go / 中断 / 待验证），禁止「今天 / 最近」。指标必带来源路径，且不跨路线裸比。
> 新记录插入到本说明块下方。
```

### 整理规范 `docs/00-规范与记录/项目知识库整理规范.md`

```markdown
# 项目知识库整理规范

## 分层
- **入口**（README）：只导航，指向当前主线。
- **规范**（本目录）：口径、填写规范、目录约定。
- **块 / 路线**：每块一个 README（当前状态）+ 一份跟踪文档（节号递增 + 变更记录）+ 最新专题报告。
- **推进记录**：时间倒序凭证，最新在上。
- **证据**：run 产物目录，文档只引用路径。

## 铁律
1. 同一状态只在一个主文档维护；跨文档事实有唯一规范位置，别处链接或一句摘要。
2. 不跨路线裸比指标；对照必带 baseline / split / seed / 数据版本。
3. 结论写清 Go/No-Go 与判据来源；用户的决定写进状态处。
4. 归档不丢证据路径（见归档清单）。
5. 不写相对时间词；文档状态与运行产物冲突时以产物为准。
6. 多个 AI 会话并行时：开工检查、跨线影响告知、收尾同步（见 skill 的 parallel-sessions）。
```
