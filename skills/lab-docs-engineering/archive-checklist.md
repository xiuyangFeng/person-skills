# 归档 / 块内收敛 / 滚动切卷清单

**前置条件**：用户在当前对话明确说「归档」「只留最新和跟踪」「切卷」或等价指令。未明确时只建议，不搬文件。

## A. 块内收敛（「文档太多，只留最新和一份跟踪」）

目标形态（profile `block_layout`）：块 README（当前状态 + 文件表）+ **一份跟踪文档**（节号递增 + 变更记录）+ **最新专题报告**；其余过程稿（方案、审议、裁定、执行记录、旧矩阵）归档。

1. 先把每份过程稿里**仍然有效的结论、裁定、证据路径**并入跟踪文档对应节（按主题或时间组织，写清出处）。
2. 再按下面 §B 归档过程稿。
3. 块 README 的文件表只列留下的文件；跟踪文档开头写「本块唯一活跃跟踪」与归档位置。
4. **代码会读的资料目录**（脚本、清单、作业日志）原地保留，只移走其中的文档；README 里写明「代码读这里，不要移动」。

## B. 归档执行

### 执行前

- [ ] 确认范围（哪些 md、哪条路线 / 块、是否含图片资产）与归档根（profile `archive.roots`，如 `<块>/_archive/<主题>_<日期>/`）
- [ ] 确认**不**移动 `outputs/`、`data*`、权重等证据目录（文档里只保留路径引用）
- [ ] 看并发：要搬的文件最近有没有别的会话在改（`git status`、mtime）；有就先协调

### 执行中

- [ ] 在**仍活跃**的跟踪 / README 写清：最终结论、Go-NoGo、替代路线、证据路径
- [ ] 移动文件（`git mv` 或 `mv`）到归档根
- [ ] **全仓 markdown 链接改写**：扫描所有 `.md` 中指向被移文件的相对链接，改到新位置；`#锚点` 保留；归档文件内部的相对链接按新层级修正
- [ ] 每份归档文档顶部加横幅：`> 已归档（YYYY-MM-DD）。现状见 [<跟踪或 README>](相对路径)。`
- [ ] 归档目录 `README.md` 登记：原名、结案日期、为何归档、结论在哪、**旧路径 → 新路径**对照
- [ ] **不改**代码、配置、划分文件、实验目录 JSON 里的旧路径字符串（它们是当时的来源记录，可能被哈希引用；运行中的队列也不能碰）——在归档 README 写明按对照表换算
- [ ] 推进记录文首记一条：归档了什么、结论留在哪里、旧→新路径表在哪

### 执行后

- [ ] 现行入口不再把归档文档当作当前待办；`grep` 确认没有正文仍把归档路径当主入口
- [ ] 断链检查：被移文件的旧路径在活文档里应为 0 次命中
- [ ] 向用户汇报：移动的文件列表、结论所在文件、旧→新路径表位置

## C. 滚动切卷（推进记录专用）

倒序追加的推进记录会无限增长，几个月后压垮可发现性。仅当用户明确要求时执行：

- [ ] 切分点按**整月**；主文件只留当前活跃区间（建议 1–2 个月或 ≤1500 行）
- [ ] 先扫日期标题（`## YYYY-MM-DD｜…`）核对乱序 / 后补条目，再按行号切
- [ ] 切分前后**条目数对账**：旧文件条目 = 新主文件 + 新卷
- [ ] 新卷放入归档根（`<日志名>_<区间>卷.md`），卷首写：来源主文件、覆盖区间、「卷内相对链接按原目录书写」
- [ ] 主文件文首加历史卷索引 + 下次切卷条件（超约 1500 行或跨季度）
- [ ] 只搬不改写；卷内旧链接不逐条修；推进记录记一条切卷动作（前后行数 / 大小）

## D. 移动类操作的通用校验

凡是「只移动、不改内容」的操作（归档、切卷、修复错位的段落）：移动前存副本，移动后对两份内容做**排序后 diff**，只允许出现新增的横幅 / 补记行，不允许丢行。

## 禁止

- 因「看起来过时」自动归档；删除历史证据或「清理」outputs
- 归档后丢弃 Go/No-Go 与关键指标（必须留在现行文档或归档 README）
- 切卷、归档、修错位时改写、合并或删减历史内容
- 改写代码 / 配置里的来源路径字符串
