# Lab Docs Engineering（科研文档工程化）· v3（2026-10）

一个**可移植的通用 Skill**：本体装一次（个人 `~/.cursor/skills/`、`~/.claude/skills/`，或某仓库的 skills 目录），
每个仓库用一份**项目内** `PROJECT_PROFILE.md` 特异化。无 profile 时先跑向导，再做业务动作。安装与分发见 [README.md](README.md)。

v3 的重点：同一个仓库常有**多个 AI 会话并行**做不同课题，各自只更新自己那块，入口、总纲、待办表里的跨文档事实就会落后、互相矛盾。
v3 增加两件事——**每个会话的收尾同步**（预防）和**全量同步审计**（定期纠偏）——并把「事实以产物为准」写成硬规则。

## 北极星（也是自检项）

科研的瓶颈常是**连续性与交接**，不是算力：重复踩坑、baseline 混表、找不到当前主线、结案后证据丢失、几份文档各说各话，才最拖进度。
每次动作后下面五条必须成立；冲突时以这五条为准，格式细则都为它们服务：

1. **决策 + 依据被固化**：结论写清 Go / No-Go 与判据来源；用户的决定（含「暂不做」）写进文档，下次不重新 litigate。
2. **不跨路线混表**（正确性问题）：不同路线 / 数据版本 / 评估集的指标不裸比；报数必带 baseline、split、seed、数据版本。
3. **可发现性**：新人或新会话从入口 README 几分钟能定位「当前主线 + 最新结论 + 下一步」。
4. **归档不丢证据**：收尾 / 归档后，现行文档仍保留 Go/No-Go 与证据路径（run 目录、图、summary）。
5. **单一事实来源，事实以产物为准**：跨文档事实（数据版本、底座及其数字、部署版本、运行中的作业、共享资源占用……）只在**一个规范位置**维护，其他位置同步或只放链接；文档里的状态必须能对上运行产物、调度器、进程和 git，对不上时以产物为准、改文档。

## 0. 每次必做：锁定 Profile

```
找 <repo>/.cursor/skills/lab-docs-engineering/PROJECT_PROFILE.md（或 profile 声明的其他位置）?
├─ 有  → 以它为准，直接做业务动作（§1 能力地图）
└─ 无  → 进向导 wizard.md，默认「A 自动推断」：扫描仓库 → 草拟 profile → 用户确认 → 落盘 → 再继续
         · 仓库尚无 docs 结构 → 「B 从零 scaffold」   · 用户要逐项手填 → 「C 完整问卷」
```

- 「初始化实验记录 / 配置本仓库文档规范 / 重新配置」：即使已有 profile 也重跑向导（先展示 diff 摘要）。
- 路径、分册、模板字段、归档策略、**事实登记表**（`fact_registry`）、活文档 / 快照的划分**以 profile 为准**；本文件只给通用流程。
- 登记表和共享资源也可以放在仓库文档里（profile 用 `fact_registry_doc` / `shared_resources_doc` 指过去）。profile 不进 git、或仓库里还有不读 skill 的 AI 时推荐这样做——规则对所有会话可见，且只有一份。
- Profile 写在**目标项目**内，不写回本体（本体保持项目无关）。发现 profile 本身过时（路线状态、状态主文档路径、节号上限）时顺手更新并在汇报里说明。

| 占用共享资源 / 依赖别的线的产物 | 在受影响的块留**跨线影响告知** | [parallel-sessions.md](parallel-sessions.md) §2 |
| 同步文档 / 文档更新到最新 / 全量同步 / 一致性检查 | **全量同步审计**：先拿事实，再扫过时说法，逐条核实，定点改 | [sync-audit.md](sync-audit.md) |

## 2. 硬边界（默认禁止）

除非用户在当前对话**明确要求**，否则不要：

- 代跑训练、提交作业、批量评测；移动 / 删除 `outputs/`、`data*`、权重等证据目录；`git commit` / `push`
- 写长篇实验复盘（分析类 Skill 的职责；本 Skill 只做结构化回填）
- 无「归档」指令时搬文件进 `_archive/`；切卷时改写历史条目
- **回滚或整段重写别的会话刚写的内容**；对别人负责的块只追加带日期的补记（见 [parallel-sessions.md](parallel-sessions.md) §4）
- 编造未跑实验的指标；把「预计 / 约…完成」当成已完成写进现状

详见 [boundaries.md](boundaries.md)。

## 3. 默认执行强度

- **直接改 md**（推进记录、跟踪、入口 README、待办、规范），改完按 [templates.md](templates.md) §汇报 说明改了什么。
- **定点修改**：精确字符串替换 + 唯一性校验；不整文件重写，不顺手重排别人的格式。
- **大改规范**（增删字段、改评估口径、改分册）：先一句话确认。归档必须用户明说。
- 用户做出的决定（「暂时不补」「先不动」「暂停」）当场写进对应文档的状态处，并注明日期与「用户决定」。

## 4. 推进记录工作流

1. 按 profile 路由表选日志；多路线拿不准先问，不混写。
2. 新条目插在「文件说明块之后、第一条旧记录之前」（最新在上）。标题 `## YYYY-MM-DD｜主题 · 动作 · 状态`（或 profile 覆盖）。
3. 状态用绝对词（已提交 / 训练中 / 完训 / No-Go / 中断 / 待验证）；不写「今天 / 最近 / 昨天」；时间写到小时并带时区口径（多机时区不同时尤其注意）。
4. 字段按 profile 的 `required_fields`；指标带来源路径，不跨路线裸比。
5. **指针条目**：事实已写在某块跟踪里时，推进记录只写一两句 + 链接，不复制正文。
6. 完成分析、核心代码变更或任务后**主动**写（属于收尾同步的一步）。

## 5. 正式入账工作流

1. 确认 profile 的 `experiment_id_rule`、run 产物根、xlsx / CSV 路径与更新工具。
2. 在路线跟踪写可追溯条目（exp_id、配置、数据版本、split、seed、关键指标、产物路径、对照）。
3. 有 xlsx 时按 `norms_dir` 内填写规范或 profile 指定的更新工具对齐；缺文件只维护 Markdown 并注明缺口。
4. 不编造未跑实验的指标。

## 6. 知识库整理工作流

1. 读 profile 分层表，区分入口 / 总纲 / 块（路线）README / 跟踪 / 规范 / 推进记录 / 报告快照 / 证据。
2. 事实写到最贴近事实的位置；入口只导航；推进记录只做时间倒序凭证。
3. 同一状态只在一个主文档维护，别处链接或一句摘要；跨文档事实按 `fact_registry` 的规范位置维护。
4. **块内收敛**（用户偏好时，见 profile `block_layout`）：每块只留 README（当前状态）+ 一份跟踪（节号递增 + 变更记录）+ 最新专题报告；新事项续写跟踪，不随手新建过程文档；过程稿在用户说「归档」后按清单搬走。
5. 清理相对时间词、修断链、修结构错位（表格行跑到表外、条目追加到错误的节）——只移动不删改，移动后做排序 diff 确认内容未变。
6. 与项目内分析 / 同步类 Skill 的边界见 [boundaries.md](boundaries.md)。

## 7. 多会话并行与全量同步

- **每个会话**都按 [parallel-sessions.md](parallel-sessions.md) 做：开工检查（读现状、看谁在改）→ 占用共享资源时留跨线影响告知 → **收尾同步**（这是预防文档分叉的主要手段）。
- **定期纠偏**：用户说「文档更新到最新 / 全量同步 / 对一遍」，或发现入口与产物对不上时，按 [sync-audit.md](sync-audit.md) 走：
  事实表 → 活文档清单 → 过时扫描 → 逐条核实 → 安全编辑 → 结构修复 → 推进记录补缺 → 汇报。
- 核心规则：**活文档改到现状，快照不改正文**（报告、汇报材料、历史卷、旧日志条目、已结束的历史小节只在其后加「后续状态（日期补记）」）；**决策原文不改**，在后面补后续。

## 8. 归档、切卷与规范演进

- 归档只在用户明说时做，严格按 [archive-checklist.md](archive-checklist.md)：证据与结论留在现行文档或 archive README；全仓 markdown 链接改到新位置；归档文档顶部加横幅；登记旧→新路径；代码 / 配置 / 划分文件里的旧路径字符串不改。
- 切卷按整月，只搬不改写，条目数对账（清单 §滚动切卷）。
- 规范小改直接改；大改先确认 → 改规范 → 同步改 profile 对应键 → 推进记录一笔。本体不绑定具体路线名。

## 9. 完成动作后的自检（30 秒）

- [ ] 结论含 **Go/No-Go + 判据来源**；用户的决定已写进状态处
- [ ] 指标带**来源路径、数据版本、评估集**，未跨路线裸比
- [ ] 入口 / 块 README 能让新人定位「当前主线 + 最新结论」，且与产物一致（作业状态、服务、git 已核对）
- [ ] 改过的跨文档事实已更新到 `fact_registry` 规范位置，镜像处同步或改为链接
- [ ] 占用 / 释放的共享资源已告知或撤销告知
- [ ] 无相对时间词；状态用绝对标签；历史内容只补记未改写
- [ ] 按 [templates.md](templates.md) §汇报 报告：改了哪些文件、发现并改正的错误、有意没改的、需要用户决定的
