# 边界与禁止项

本文件项目无关；具体的分析类 skill 名、路线名、批量脚本名、共享资源以本仓 `PROJECT_PROFILE.md` 为准。

## 本 Skill 负责

- 推进记录、入账 Markdown、规范小步演进、知识库分层整理、**用户明确要求的**归档与切卷
- 多会话并行协议：开工检查、跨线影响告知、收尾同步（[parallel-sessions.md](parallel-sessions.md)）
- 全量同步审计：核对活文档与产物、改到现状、修结构错位、补推进记录（[sync-audit.md](sync-audit.md)）
- 无 profile 时的配置向导（含从零 scaffold）；profile 过时时的小步更新
- 分析结束后的**短回填**

## 不负责（交给其他 Skill / 人工）

| 事项 | 归属 |
| --- | --- |
| 读 summary / history、出对比图、写长篇复盘 | 分析类 Skill（profile `analysis_boundary.skill_name`） |
| 训练、提交作业、批量评测 / 对比、补跑中断的实验 | 仅当用户明确要求；不是本 Skill 主路径。同步审计只**核查**作业状态，不重跑 |
| 改代码、改数据、改配置 | 对应任务本身；本 Skill 只记录 |
| git commit / push、发布到公开仓库 | 仅当用户明确要求 |
| 工作簿 / 图 / HTML 等非 Markdown 产物 | 用 profile 指定的工具或分析 Skill；同步审计只在汇报里列待办 |

## 与分析类 Skill 衔接

1. 分析 Skill 产出 Go/No-Go 与指标后，本 Skill 做收尾同步（推进记录 + 跟踪 + 块 README + 事实镜像）。
2. 不在本 Skill 内重做曲线对比或凭记忆报数；数字指回读数文件。
3. 用户只说「记一下」且上下文已有分析结论：直接回填。

## 与其他同步 / 整理类 Skill 重叠时

1. 用户点名某个同步类 Skill：优先跟它；本 Skill 的分层表与 `fact_registry` 可作对照。
2. 用户点名本 Skill，或说「写推进记录 / 初始化实验记录 / 全量同步」：跟本 Skill。
3. 两者都可能改入口 README：先读现有结构，小步改导航，不推翻未读完的分层。

## 多会话并行时的边界

- 自己负责的块直接改；别的会话负责的块只**追加**带日期、带依据的补记或告知，不改它的实验内容和结论。
- 不回滚别人的改动；认为有错先用产物核实，改了要在补记里写依据；拿不准问用户。
- 别的会话 30 分钟内改过的文件，重读后再定点修改，能追加就只追加。
- 不替别的线做决定（例如要不要补跑、要不要切换部署）：只把事实和选项写清，交给用户。

## 硬禁止（默认）

- 代跑训练 / 提交作业 / 批量对比脚本（除非用户明确要求）
- 移动或删除大数据与证据目录（`outputs/`、`data*`、模型权重等）
- 自动 git commit / push
- **跨路线混表对比指标**（profile `routes[].no_cross_metrics`）——正确性红线，不是格式偏好
- 无用户「归档」指令时把文档搬进 `_archive/`；切卷 / 归档 / 修错位时改写历史内容
- 整文件重写别人维护的文档；改写决策记录原文、带日期的报告与历史卷正文
- 编造未跑实验的指标；把「预计 / 约…完成」当作已完成；写「今天 / 最近」等相对时间词
- 改写代码 / 配置 / 划分文件里的来源路径字符串
